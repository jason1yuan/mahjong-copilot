# profiles — 游戏适配包

每款游戏一个子目录，接入新游戏只加适配包，不改核心代码。适配包只是一个 JSON：只有数字和文字，不含任何游戏截图或素材（游戏美术不能随 app 分发）。包含：

- 窗口匹配规则：应用名、窗口标题、浏览器标签页标题
- 版面比例：以手牌为锚点（#3）。手牌按牌面检测找到；游戏区域按牌间距和手牌位置推出。其他区域：
  - 四家牌河和副露（#8）：
    - `table.corners`：桌面到屏幕的透视变换，即桌面上 (±6, ±6) 四个点在游戏区域里的位置。桌面坐标以牌宽为单位，原点在桌子中心，自家朝 +y；
    - `river`：牌河版面，用自家的坐标写，其他三家按四分之一圈转过去：`left` 第一列左边，`near` 第一行近边离中心多远，`row_pitch` 行距，`columns` 每行几张；
    - `melds`：副露所在的带子，同样用自家的坐标写：`left`、`right`、`near`、`far` 围出带子，副露从右端往左排，第一张牌的右边要在 `start_after` 右边；
    - 这些数字用 `ml/calibrate/table.py` 从录下的画面里拟合，见 `perception/README.md`；
  - `dora`：宝牌指示框（#8），相对手牌牌距的牌面宽高（`width`、`height`）、格距（`pitch`）和格数（`slots`），用来在左上角查找那排格子；`sticks`、`honba` 是框下供托和本场计数的位置（#9），从第一张指示牌的左上角量起，单位是手牌牌距；
  - `centre`：中央框（#9）：四家风牌的位置和大小（`markers`、`marker`）、局数标签（`label`）、余牌数的数字（`tiles_left`），以及四家分数（`scores`，每家按自己的坐标写）；
  - `buttons`：动作按钮（#9），相对游戏区域的比例：`skip` 是跳过按钮的框，`first` 是紧挨着它左边的那一格，往左每隔 `pitch` 还有一格，共 `slots` 格；只取每个按钮中间那段，避开两头的斜边。`hues` 是每种按钮的颜色（色相，单位度）
- 牌面颜色阈值：找牌面用

牌面不用预先准备：运行时由认牌模型认出并缓存成模板（见 `perception`）。

第一个适配包：[`majsoul-web`](majsoul-web/)（雀魂网页版）。
